A.1  CONVENTIONS REUSED FROM 09_dq90_duration_hazard.py
-------------------------------------------------------------------------------------------------------------------------
    DQ90+ loan-month             
        numeric field-4 status >= 3. 98 and 99 are inside it (D12: 99 is the documented cap, not a sentinel). RA packs
        to -1 and any other non-numeric value to -2, so the test 'status >= 3' can never catch RA or XX.
    run start / end              
        a run continues only across an OBSERVED, immediately preceding DQ90+ month of the same loan. Every other row
        opens a new run. Run-length is the distance from the run's opening row, 1-based.
    gap handling                 
        a hole in the reporting periods breaks the run and the counter restarts at 1. A repeated (loan, period) is not
        adjacent either, so it restarts a run too; the count is reported.
    run-length buckets           
        1, 2, 3, 4-6, 7-12, 13-24, 25+ - exactly 09's.
    terminal zero-balance row    
        a DQ90+ month that is itself the loan's last observed row and carries a terminating zero-balance code
        (01/02/03/09/15/16/96). 09 keeps these inside the slice. T1 primary keeps them; T1 sensitivity removes them.
    chunk-boundary carry-over    
        none is needed. Pass 1 finds the loans that ever reach DQ90+ in the file; pass 2 keeps every row of exactly
        those loans as packed integer arrays; the arrays are lexsorted by (loan, period) after the whole file is read.
        A loan straddling a chunk boundary is reassembled by that sort, not by boundary state. This is 09's mechanism
        unchanged.
    loans do not straddle files  
        the identifier carries its own vintage prefix. The prefix seen in each file is reported below so the assumption
        is checked rather than assumed.

    Departure from 09: pass 1 reads three columns (0, 1, 3) instead of four - it has no use for the zero-balance code -
    and pass 2 reads seven (0, 1, 3, 7, 8, 24, 29) instead of four. This is a read-width change only. No definition above
    is affected, and the slice totals are re-checked against 09's published figures in B.1.

A.3  ARE THE THREE FLAGS CURRENT-MONTH OR PERSISTENT? THE GUIDE'S OWN WORDS
-------------------------------------------------------------------------------------------------------------------------
    source : docs/general_user_guide_july_2026.pdf, Monthly Performance Data File

    field  8 (index  7)  Modification Flag
    .................................................................................................................
      Description
        "A flag indicating if the loan has been modified in the current period or a
         prior period.
    
         Note: Due to the various loan modification programs available to borrowers,
         a loan could have been modified more than once. In these cases, the
         modification flag will be set to "Y" in more than one monthly reporting
         period."
    
      Enumerations
        "Y = Current Period Modification
         P = Prior Period Modification
    
         Null = Not Modified"

      CLASSIFICATION: PERSISTENT
        'or a prior period', and the separate enumeration P = Prior Period Modification, make this an EVER flag: once a
        modification happens the field stays populated. Onset is therefore Y, not 'non-null'.
        Activity test used in T7: flag value == 'Y' (onset).

    field 25 (index 24)  Payment Deferral Flag
    .................................................................................................................
      Description
        "A flag indicating a loan has been granted a Payment Deferral in the current
         or prior period."
    
      Enumerations
        "C = Current Period
         P = Prior Period"

      CLASSIFICATION: PERSISTENT
        'in the current or prior period', with P = Prior Period, makes this an EVER flag on the same pattern. Onset is
        C.
        Activity test used in T7: flag value == 'C' (onset).

    field 30 (index 29)  Borrower Assistance Plan
    .................................................................................................................
      Description
        "Regardless of delinquency status, the type of assistance plan that the
         borrower is enrolled in that provides temporary mortgage payment relief or
         an opportunity to cure a mortgage delinquency over a defined period.
    
         Note: Only populated for January 2014 and following periods."
    
      Enumerations
        "F = Forbearance
         R = Repayment
         T = Trial Period
    
         Null = No workout plan or not applicable"

      CLASSIFICATION: CURRENT-MONTH
        the enumeration carries no prior-period value and the description is in the present tense - the plan the
        borrower 'is enrolled in'. This is a CURRENT-MONTH indicator, so the flag VALUE is used, not an onset. The
        January 2014 restriction bites hard on these vintages: the 2007-2011 window this cohort exists to observe is
        entirely before it.
        Activity test used in T7: flag value is non-null (F, R or T).

A.4  CONSEQUENCE FOR T7
-------------------------------------------------------------------------------------------------------------------------
    Because Modification Flag and Payment Deferral Flag are EVER flags, testing them for 'non-null' at a departure month
    would mark every month after the first modification, not the month the modification happened. T7 therefore tests
    ONSET for those two - Y and C respectively - and the VALUE for Borrower Assistance Plan, which carries no
    prior-period code. A departure is credited to a flag if the onset or value appears at the departure month itself or
    at the immediately preceding observed month, where that preceding month exists and is exactly one period earlier.

=========================================================================================================================
T6  STICKINESS - is an off-step month the run's first departure, or downstream of one?
=========================================================================================================================
    Within a run, departures are counted from the run's opening row forward. A loan-month is the FIRST departure when it
    is the earliest off-step month of its own run; it is DOWNSTREAM when an earlier month of the same run was already
    off-step. Once field 4 falls behind the ladder it cannot rejoin it, because the ladder keeps advancing by one a month
    and field 4 can advance by at most one a month - so a high downstream share is arithmetic, and the first-departure
    count is the number of distinct departure EVENTS.

                                        loan-months        share       share of slice
-------------------------------------------------------------------------------------------------------------------------
first departure of its run                  224,651       10.29%               3.476%
downstream of an earlier one              1,958,254       89.71%              30.298%
-------------------------------------------------------------------------------------------------------------------------
all off-step loan-months                  2,182,905      100.00%              33.774%

    Reconciles with T1 off_below + off_above (2,182,905): yes
    Distinct departure events per DQ90+ run: 224,651 first departures / 605,140 runs = 0.371

=========================================================================================================================
T7  FIRST DEPARTURES - when they happen, and what is flagged at the time
=========================================================================================================================
Unit: first-departure loan-months (T6 row 1), filed under the run-month at which the
departure occurs. A departure is credited to a flag if the flag fires at the departure
month itself OR at the immediately preceding observed month, one period earlier:
    modification   flag value 'Y'  (ONSET - the field is persistent, A.3)
    deferral       flag value 'C'  (ONSET - the field is persistent, A.3)
    assistance     flag value F/R/T (VALUE - the field is current-month, A.3)
The three are not exclusive, so mod + defer + assist may exceed 'any of the three'.
'no prior month' counts departures whose preceding observed row is absent or is not
exactly one period earlier; for those, only the departure month itself was testable.
The run-month 1 row is empty by construction, not for want of data: at k = 1 the
expected status IS the entry status, so deviation is 0 and no run can first depart there.
