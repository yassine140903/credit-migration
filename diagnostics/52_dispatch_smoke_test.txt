0. WHAT THE REAL SCRIPTS OFFER  (read from the source in this session; reported before anything runs)
============================================================================================================================
src/train_ml.py: options --name --with-loan-age --origin-states --from-period-max --overwrite. NO row-cap option; NO round-count option (N_ROUNDS = 100, a module constant).
   from_state is a feature iff len(origin_states) > 1 (resolve(): pooled = len(origin) > 1); the sidecar records features, categories, class_order, origin_states,
   from_state_is_feature, label_counts, n_rows, training_window, n_rounds. params declare num_class = 6 whatever the labels contain.
src/forecast.py: --model-map STATE=DIR (one Model per distinct directory; unique_models() gives one frame per model). Model.__init__ REQUIRES sidecar class_order == panel.STATES
   (forecast.py:123), booster feature names == sidecar features (:125) and num_model_per_iteration == 6 (:128). propagate() writes out[k*n:(k+1)*n] into trans[:, o, :] (:283-285)
   with no class mapping and no zero-fill of any column. build_frame() takes the column list from the model's own sidecar features (from_state only if listed).
So the three-model dispatch (--model-map, a frame per model, feature order and from_state keyed off each sidecar) IS implemented; a zero-fill of absent classes is not in the code.
Consequence for this diagnostic: nothing needed to STOP on 'dispatch not implemented'. The cap and rounds are applied by patching module attributes in this process only (see the docstring).
